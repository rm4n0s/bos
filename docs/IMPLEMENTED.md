## Step 6 – ComfyUI adapter and event hub
- Branch: feat/comfy
- Last code commit: 3883b60
- Date: 2026-10-09
- Delivered: `internal/comfy`: the `Client` port of SPEC §18.2 with `NodeWarning`, `OutputFile` and `Result`; `Server`, its adapter over `comfyui-client-go`. One hub per server connection: a single goroutine is the only consumer of `Listen`, routes the end of each prompt (`execution_success`, `execution_error`, `execution_interrupted`) to the waiter of its prompt id, keeps the ends of unwatched prompts in a bounded, expiring buffer, and ignores `status` events as completion (§18.3.1–3). The connection is kept up in the background: a lost socket gets a new client with a new client id and back-off, and the uploads remembered for the old connection are dropped (§18.3.4). `Wait` combines the event stream with a poll of the history and the queue, so a prompt that finished while the socket was down, a prompt of an earlier run of the application and a prompt queued without a connection all complete without being run again; a prompt that is in neither history nor queue is `ComfyUIPromptLost`; repeated failed polls are `ServerUnreachable` (§18.3.5, §18.7). `QueuePrompt` keeps a prompt that ComfyUI accepted with node errors and returns them as warnings, and rejects one without an id with `ComfyUIRejected` (§18.7). `Upload` names files by the SHA-256 of their content in the `bos` input sub-folder, uploads each once per server even for 100 concurrent callers, and returns the name ComfyUI gave (§18.6). `Cancel` deletes a pending prompt or interrupts a running one and warns once per server when ComfyUI is older than 0.3.57. Errors of the library are mapped at the boundary. Tests run against an `httptest` fake ComfyUI with a WebSocket endpoint and cover routing of interleaved prompts, early events, polling-only completion, a restart, connection loss and reconnection with a new client id (acceptance 34), node errors (35), upload deduplication (36), failure details with traceback, interruption, cancellation, an unreachable server, cancellation by the caller's context, and `Close` leaving no socket open; repeated under `-race`.
- Checks: gofmt ✔  go vet ✔  golangci-lint ✔  go test -race ✔
- Deviations from the spec:
  - New error tags, to be added to the ComfyUI row of §17.2: `ComfyUIInterrupted` (the prompt was interrupted; `execution_interrupted`), `ComfyUIPromptLost` (neither running, queued nor in the history), `ComfyUICallCancelled` (the caller's context ended; the scheduler stops quietly on it instead of failing the job), `ServerHostInvalid` (the host is not an http(s) URL; 422).
  - §18.3.4 says all waiters fail with `ServerUnreachable` when the socket drops. A waiter keeps going instead, by polling, and fails only when the polls themselves fail `PollFailures` times (default 3): the socket is an accelerator, the history is the truth. This is what acceptance test 34 needs and is what the same section's step 5 describes.
  - Only 502, 503 and 504 answers count as an unreachable server; any other status is ComfyUI's own answer and gets the tag of the operation (`ComfyUIRejected`, `ComfyUIUploadFailed`, `ComfyUIResultMissing`).
  - `Result` groups output files by node id; the scheduler picks the generator's output node (found by its title) with `Result.Pick`, which raises `ComfyUIResultMissing` when the node produced no file. A prompt whose nodes were all served from ComfyUI's cache can come back with no outputs; a random seed avoids it.
  - `Server.Connected()` and `Options.OnConnection` tell the scheduler whether the event socket is up. The availability probe of §8.1 is `Ping`, which the scheduler (step 8) calls every second; the adapter does not run it.
  - `github.com/gorilla/websocket` is now also a direct dependency, because the fake server of the tests uses it; production code does not import it.

## Change – Store on gorm (outside the numbered steps)
- Branch: feat/store-gorm
- Last code commit: 99d29f8
- Date: 2026-10-09
- Delivered: `internal/store` now uses `gorm.io/gorm` with its official driver `gorm.io/driver/sqlite`, at the request of the project owner, who does not want hand-written SQL. The public API of the store (`Open`, `Migrate`, `SchemaVersion`, `InTx`, `Repos` and every repository method) and its error tags are unchanged, so no other package is affected. Each table has a record struct (`models.go`) that converts to and from its domain type, so `internal/domain` stays free of storage tags; JSON columns and the 64-bit seed use small column types (`jsoncol.go`). The schema is built by numbered Go migrations (`migrate.go`) that use gorm's `Migrator` on structs frozen for migration 1 (`schema_v1.go`); `internal/store/migrations/0001_init.sql` is gone. The migrated schema has the same tables, columns, unique and plain indexes, foreign keys (no `ON DELETE CASCADE`) and check constraint as before. A test checks that the records match the migrated tables, and others cover the migration order, rollback of a failed migration and bad versions. The repository tests are unchanged apart from the places that used SQL directly, which use gorm. The old tests, including 16 workers claiming one job and 8 workers draining 120 jobs on in-memory and file databases, pass under `-race`, repeated.
- Checks: gofmt ✔  go vet ✔  golangci-lint ✔  go test -race ✔
- Deviations from the spec:
  - SPEC §14.4 D1 and D8, the storage row of §14.1, the dependency list and `CLAUDE.md` / `IMPLEMENTATION.md` are updated in this change to say gorm, its SQLite driver and Go migrations.
  - The driver is gorm's official one, as the project owner chose, and it uses `github.com/mattn/go-sqlite3`, which needs cgo. The project therefore builds and runs only with `CGO_ENABLED=1` and a C compiler (the GitHub Actions runner has one). With cgo off, `go build` still succeeds but opening the database fails at run time. A first build compiles the SQLite C source once (a compiler warning from it is harmless) and is cached afterwards. This replaces the pure-Go `modernc.org/sqlite` of the original D1 and the `github.com/glebarez/sqlite` driver of the first version of this change, so `modernc.org/sqlite` is no longer a dependency. The connection options are those of go-sqlite3 (`_busy_timeout`, `_foreign_keys`, `_txlock=immediate`, `_journal_mode=WAL`).
  - A database file made by the earlier SQL migration is not read by this version: it stored timestamps as text and the new records read `datetime` columns. Nothing has been deployed, so no conversion is provided; delete such a file.
  - gorm's builder is given a few SQL fragments where it has no other way: `COALESCE(MAX(...))`, `COUNT(*)`, `order_no + 1`, `instr(lower(...))` and `LIKE ... ESCAPE`. No statement is written by hand.
  - A failed rollback no longer adds `rollback_error` to the error's metadata, because gorm does not report it.
